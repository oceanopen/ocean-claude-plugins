# 待办列表记录与跟进

## 1. 唯一入口与意图路由

入口仅为待办事项文本（命令参数或对话输入），按以下规则智能判断意图并直接执行；仅在意图或匹配结果真正无法判断时才询问用户：

| 输入 | 行为 |
|---|---|
| 无参数 | 读取 `todo-list/index.md`，返回总索引概览（模块清单、各模块待办数与状态分布） |
| 待办文本，查到唯一 | 返回该待办完整信息；输入同时携带新进展/状态变化则同步更新该条（更新 frontmatter `状态` 与 `更新日期`，`进展` 追加一行） |
| 待办文本，查到多个候选 | 一并返回候选清单供定位；能明确命中其一且输入携带新进展时更新之，无法判断时列候选询问 |
| 待办文本，未查到 | 判定归属模块（现有模块或新建模块），自动新增待办文件并同步索引 |
| 明确操作指令（完成/取消/删除某待办等） | 执行对应增删改查，同步索引 |

**检索规则**：以待办文本为关键词，用 Bash（`rg`/`find`/`grep`）检索全部待办文件名、frontmatter `事项` 字段与各模块索引条目；关键词包含与语义相近均算命中，不依赖其他查找类工具。

## 2. 目录铁律（不可违反）

- 一切文件操作**严格局限在当前工作目录的 `todo-list/` 目录内**：新增、修改、删除只允许作用于该目录内的文件，不在目录外产生或修改任何文件——同一工作目录可能有多个技能并行运行，零外溢是硬约束
- 目录不存在时自动创建完整骨架（根索引 + 首个模块目录 + 模块索引）
- 检索与列目录一律用 Bash 等价命令完成

## 3. 目录结构

```
todo-list/
  index.md            # 总索引（必须存在，缺失即按模板重建）
  <模块目录>/          # 待办必须按模块归档，不允许散落在根下
    index.md          # 模块索引（必须存在）
    <待办>.md         # 每条待办一个文件
    files/            # 按需：当前任务需要关注的文件统一整理到此目录
```

## 4. 待办记录模板

```markdown
---
事项: <一句话事项名>
状态: 待开始 | 进行中 | 已完成 | 已取消
关注人: <人名，多人逗号分隔，无则写 - >
创建日期: YYYY-MM-DD
更新日期: YYYY-MM-DD
截止日期: YYYY-MM-DD   # 无明确截止则整行省略
---

## 详情

<背景、目标、上下文，按需>

## 进展

- [YYYY-MM-DD] <创建时写入一行；后续每次更新追加，新的在上>
```

文件名 = 事项名（去除路径非法字符），与 frontmatter `事项` 保持一致，保证索引与检索直观。

## 5. 索引模板

根 `index.md`（总索引）：

```markdown
# 待办总索引

| 模块 | 待办数 | 进行中 | 最近更新 |
|---|---|---|---|
| <模块目录名> | N | N | YYYY-MM-DD |
```

模块 `index.md`（模块索引）：

```markdown
# <模块名>

| 事项 | 状态 | 关注人 | 截止日期 | 更新日期 |
|---|---|---|---|---|
| [<事项>](<待办文件>.md) | 进行中 | xxx | YYYY-MM-DD | YYYY-MM-DD |
```

## 6. 索引同步

每次新增/更新/删除待办后，立即同步刷新两级索引：所属模块 `index.md` 对应行，根 `index.md` 对应模块行（待办数、进行中数、最近更新日期）。发现索引与待办文件不一致时，以待办文件为准重建索引。

## 7. 模块自动梳理

- **归属判定**：新增待办时按语义匹配现有模块，无合适模块则新建；模块划分维度（按业务域、项目、主题等）自行判断，不询问用户
- **拆分与合并**：模块内容过多过杂时自动按更细维度拆分（模块目录是最小粒度，拆分后仍过杂则按子主题再拆）；模块过空时合并。过程中完成待办文件迁移与两级索引重建，全程不询问用户
- **命名**：模块目录名中文 ≤10 字、英文 ≤30 字符，简洁清晰
- **与时俱进**：待办结构演化导致现有划分不清晰时，随时重命名、重组模块（旧目录名不作历史包袱）；迁移时保持待办文件内容不变，仅调整归档位置与索引
